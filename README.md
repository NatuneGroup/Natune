**ArchiveTune** isn’t just another generic YouTube Music wrapper. It’s a fully custom-built player made from the ground up, because we think your music should stay private, look clean, and work exactly the way you expect. If you care about sound quality and want something that actually feels good to use, this is it.

> [!IMPORTANT]  
> **Geographic Availability:** If YouTube Music is not supported in your region, a VPN or proxy set to a supported region is required for initial data fetching.

### Release Channels

ArchiveTune has two update channels:

- **Stable** is built from the `main` branch and published as regular GitHub releases.
- **Nightly** is built from the `dev` branch and published as `N`-tagged GitHub pre-releases (for example `N202610141200`). It gets new features first and may be less polished.

Both channels are signed with the same key, so updates install over the existing app in place.

The former Canary channel (`C`-tagged pre-releases from the `canary` branch) has been retired. Final Canary `C202610141722` shipped at `a1a04ea02`; the branch is frozen. A stored Canary choice migrates to Nightly.

The in-app updater first reads a small update manifest (`stable.json` or `nightly.json`) that CI publishes on the `update-feed` release. That download needs no GitHub key and does not count against GitHub's API rate limit; the updater only falls back to the GitHub API when the manifest is unavailable.

### Delivered in Nightly N202610151104

PR #198 merged at `643a35fd09888769a4a2d588324398d68f0d6fb5` and shipped
Nightly **N202610151104 / build 6833**. Its separate exact-head build and unit-test
gates succeeded: **835 passed, 0 failed, 0 skipped**. These are historical results,
not validation of the new YouTube follow-up below. Lint ran under the inherited
permissive policy (318 Error / 745 Warning / 43 Hint), not a lint-clean result.

- Stable and Nightly remain explicit user choices on every build; build identity supplies only the unset default. Offers retain channel association and require a known newer version code.
- Visible overflowing settings descriptions scroll automatically for finite passes, respecting lifecycle and reduced motion. Restart-scoped edits keep the running values until restart and share one **Restart now / Later** dialog after persistence; Later never restarts automatically.
- The acoustic heat graph is available in Developer settings and shared player/song menus. Opening it does not analyze: **Run / Cancel / Retry** owns a bounded, source-bound excerpt. Seekable local file/content, supported clear current streams and complete source-bound cache are supported; DRM/inaccessible inputs can be unavailable. Spectral suspicion is heuristic, not proof of original losslessness or physical DAC output.
- Existing DSP maintenance updates Oboe to 1.11.0, Signalsmith Linear to 0.6.5 and retained libusb to 1.0.30; Stretch stays 1.4.0 and soxr 0.1.3. No new engine or default audio policy. libusb/soxr are trimmed Android subsets, rebuilt through the app's CMake/Gradle path, not full standalone upstream test distributions. Active USB output remains; only an unreachable older USB module was removed, with its MIT license retained.
- Integrated lyrics changes preserve semantic Unicode, use conservative script-family exclusions and metadata/kana-aware phonetics, and give SimpMusic the shared built-in/provider/AI policy with shaped, source-spaced timed text. Unaligned readings fall back to a line instead of invented word timing; this is not exact language detection or universal pronunciation.
- AI translation accepts complete validated results, keeps failures retryable and binds caches/results to settings and the current lyrics target. DeepL has explicit target codes and does not claim romanization support. All active translation surfaces invalidate changed targets; automatic calls retain exclusion gates. Downloader requests own separate staging/latches; Listen Together retries retain connection/request identity; Spotify refresh/sign-in/sign-out serialize account mutation.
- Japanese dictionary automation uses primary system-device locale region JP, never IP geolocation. One persisted best-effort foreground consideration may download over Wi-Fi or cellular; offline consumes that consideration, with manual retry still available. Explicit off/removal prevents automatic installation. Download/checksum/tokenizer work stays off the startup/render thread, and the pinned 13,343,016-byte IPADIC pack is optional offline-romaji data, not UI translation or a universal language engine.

The delivered release includes the focused production-tokenizer/IPADIC fixtures.
No device, visual, USB or all-language validation is claimed.

### YouTube follow-up (local source; uncompiled and unreleased)

- Ordinary playlists now use an app-owned **finite browse queue**, separate from RD/Mix
  and explicit radio. Paging preserves entry occurrences (including repeated videos),
  selected-track position, manual additions and existing filtering/repeat policies.
  Recommendations require confirmed finite exhaustion and the existing autoplay policy;
  missing legacy state or a failed page cannot silently become radio.
- New queue snapshots retain finite paging/occurrence state. Legacy queues keep saved
  items and position; only unambiguous order-preserving alignment permits recovery.
  Otherwise **Retry / Cancel / Reload** remains explicit instead of guessing order or completion.
- Whole-playlist **Add to queue / Play next / import / sync** requires strict complete
  loading before insertion or saved-playlist replacement. Failed, stalled or bounded loading
  is incomplete, never partial success. Ordinary **Shuffle** loads the complete finite list
  and uses client-side shuffle, not the exact server shuffle sequence. No fixed 80-track
  server limit has been established.
- Login recovery addresses the observed embedded **`net::ERR_UNKNOWN_URL_SCHEME`**
  for a Music store intent, not a proven renderer crash. Narrow official install targets
  get one guarded HTTPS Music return in the **same WebView**, with visible loading/errors
  and Retry/Cancel. Normal DOM storage and the cookie jar survive entry/return/retry;
  logout expires YouTube scopes rather than wiping unrelated provider storage.
- Candidate cookie/visitor/account context stays private in memory until final-context
  account verification on a reusable private client succeeds. Only a current verified
  attempt commits identity/context together; failure/cancel preserves the previous account,
  and obsolete callbacks/refreshes cannot overwrite a newer session.
- Existing anonymous **MetrolistGroup/innertubex v0.9.2** is pinned at
  `c19d4860b0bc8afa0b1b3cc717abeb8119bbb605` (GPL-3.0 unchanged).
  This library update is not the playlist or login fix. Manual primary-client choice,
  terminal login errors and **YTPlayerUtils → InnerTubeX → NewPipe → Echo** remain;
  no personal/pool cookie bridge or new HLS/SABR/bounded-range transport is enabled.

### 🛠️ Development & Engineering
Interested in building the project or contributing? ArchiveTune is built on a high-performance Kotlin stack.
<a href="CONTRIBUTING.md"><b>Read the Build & Contribution Guide →</b></a>

Use JDK 21, Android compile SDK 37 and NDK `30.0.16248370`, the checked-in Gradle
9.6.1 wrapper and recursive submodules. The debug app runs on Android 8.0/API 26+.
Build/lint with `./gradlew assembleGmsMobileUniversalDebug lintGmsMobileUniversalDebug`;
tests use `./gradlew :app:testGmsMobileUniversalDebugUnitTest`. In the private KMP
workspace these are final-phase commands: the code-only phase runs no build, test, lint,
checker or launch command until the full port is integrated and verification is
authorized (see the private KMP status below). That deferral belongs to this constrained
mission, not to ordinary contributor setup. See [release gates](docs/claude/RELEASES.md)
before publishing.

opens one `DesktopSessionGraph` after its single-instance lock: the ordinary settings file and
the platform credential vault behind one `VaultSettingsStore`, one provider account store, one
portable database v5, the library, artist-block and listening-history repositories, one playback
port and player, one queue owner with its checkpoint store, and one listen-history driver. It
mounts `ArchiveTuneRoot` over that graph through `DesktopHostBindings`. Window visibility and
resume feed the root's inputs; hiding the window never pauses audio. Closing the window hides it to
the tray only when the observed hide-to-tray preference is on and a tray is available; otherwise the
close exits. The library and playlist pages, with liked songs and My Top reached through their
routes, deep links and the Library's More menu, open from the shell over the graph's own library,
block and listen owners, and Alt+Left goes back. The Playlists create dialog saves a new local
playlist through the library owner and opens it when the save completes. Their rows play,
play next, add to queue, or start a shuffled copy of a list in the one queue, and the player's
previous, next, repeat, seek and like controls drive the same graph; like reads and writes the owner's
liked list for the current song. Audio sources resolve through the
ordered chain. The public Qobuz backup mirror is composed over one HTTP client and stays off until
it is enabled in settings. Every other source answers as unavailable until its account or decoder
owner is connected. YouTube and local files are not connected, and a queue load that no source
answers fails with the attempts it made. Item, news and player artwork load over that same client as public http or https images, sent with no cookie or account header, and a failed or oversized image keeps its placeholder frame. Desktop run, not executed in this phase: `./gradlew :desktopApp:run --max-workers=1 --no-daemon`
with JDK 21. Session data lives in `~/.archivetune/desktop`; a JVM started directly can point it
elsewhere with `-Darchivetune.instance.directory=<dir>`. Credentials are written only to the platform
credential store (Secret Service on Linux, the keychain on macOS, DPAPI on Windows), never to
plaintext. The window shows the unavailable boundary when a stored credential reference exists and
the store cannot return it. With no stored credential the graph still opens, and a credential write
that needs the store fails explicitly.
